# Как вести бэклог

[← К бэклогу](../README.md)

## Как всё устроено

```
tasks/            активные задачи — один файл на задачу
archive/2026/     закрытые задачи (готово / отменено), ничего не удаляется
templates/task.md шаблон карточки
dashboard/        страница дашборда (GitHub Pages)
scripts/build.py  сборка сводки, архива и данных дашборда
README.md         сводка — собирается автоматически, руками не править
```

После любого изменения в репозитории робот (GitHub Actions) за ~1 минуту:

1. переносит задачи со статусом `done` / `canceled` в `archive/<год>/` и проставляет дату закрытия;
2. возвращает задачу из архива в `tasks/`, если ей снова дали активный статус;
3. пересобирает `README.md`, `archive/README.md` и дашборд.

Раз в сутки (в 00:05 по Екатеринбургу) сводка пересобирается сама, чтобы «осталось N дней» было актуальным.

## Три способа работать с задачами

| Способ | Когда удобно | Как |
|:--|:--|:--|
| **Через Claude** (проект «Бэклог») | Новая задача с контекстом, пачка задач, разбор письма или переписки, еженедельный пересмотр приоритетов | Пишете в свободной форме — Claude оформляет карточку и коммитит |
| **Форма «＋ Новая задача»** | Быстро записать задачу на бегу, с телефона | Кнопка в README или на дашборде → заполнить поля → робот создаст карточку и закроет заявку |
| **Правка файла на GitHub** | Сменить статус, срок, приоритет, дописать строчку в журнал | Открыть файл задачи → ✎ → поправить → Commit changes |

Рекомендуемая схема: новые задачи — через Claude или форму, мелкие правки — сами прямо на GitHub.

## Поля карточки

| Поле | Значения |
|:--|:--|
| `status` | `inbox` — входящие, не разобрано · `backlog` — разобрано, ждёт очереди · `in-progress` — в работе · `waiting` — ждём других · `done` — готово · `canceled` — отменено |
| `priority` | `must` · `should` · `could` · `wont` (см. ниже) |
| `type` | `analysis` — аналитика · `dev` — разработка · `consult` — консультация · `research` — исследование · `support` — поддержка |
| `deadline`, `created`, `closed` | даты в формате `2026-10-15` |
| `estimate` | свободно: `2h`, `1d`, `3d` |
| `tags` | `[отчёты, регламенты]` |

Статусы, приоритеты и типы можно писать и по-русски (`в работе`, `обязательно`, `разработка`) — робот поймёт.

## Приоритеты по MoSCoW

- **Must** — без этого нельзя: остановится процесс, будут деньги/штрафы, прямое поручение руководства со сроком.
- **Should** — важно и нужно, но есть обходной путь; делаем сразу после Must.
- **Could** — улучшение «было бы хорошо»; берём, когда есть окно.
- **Won't (сейчас)** — осознанно отложено; не удаляется, пересматривается раз в месяц.

Приоритет отвечает на вопрос «насколько важно», срок — «насколько срочно». Внутри каждой группы задачи отсортированы по сроку, а всё, что просрочено или горит в ближайшие 3 дня, поднимается в блок «Горит» наверху сводки.

Ориентир: Must — не больше трети активных задач. Если Must становится всё, приоритеты перестают работать.

## Ритм

- **Каждый день** — смотрю «Горит» и «В работе» на дашборде.
- **Раз в неделю** — разбираю «Входящие», пересматриваю Must/Should, обновляю сроки.
- **Раз в месяц** — просматриваю Won't и Could, лишнее — в `canceled` с причиной в журнале.

## Закрытие задачи

Поставить `status: done` (или `canceled`) и дописать строку в «Журнал» с результатом. Остальное сделает робот.
