## 1. Где что смотреть

| Что | Зачем | Когда открывать |
|:--|:--|:--|
| **[Дашборд](https://tork059.github.io/resan-revitech-backlog/)** | Главный рабочий экран: что горит, что в работе, что следующее. Поиск и фильтры, полная карточка по клику | Каждый день, с ПК и телефона |
| **[README](../README.md)** — главная страница репозитория | Та же сводка текстом: проекты, «Горит», таблицы по горизонту и MoSCoW | Когда удобнее таблица или нужен быстрый взгляд из GitHub |
| **Карточка задачи** — файл в `tasks/` | Весь контекст: суть, зачем, чек-лист, критерии готовности, материалы, журнал | Перед тем как взяться за задачу |
| **[Архив](../archive/README.md)** | Все закрытые задачи по месяцам, с датой закрытия | При отчёте о сделанном |

**Вкладки дашборда**

- **Спринт** — главный экран. **В работе** — делаю сейчас; **Готово к реализации** — можно передавать разработчикам; **В разработке** — передано разработчикам; **На тестировании** — проверка результата; **Запланировано** — выполнение в рамках месяца; **Отложено** — запланировано в рамках более месяца. Колонки выбираются вручную. Дедлайн влияет на подсветку и порядок внутри колонки, но не перемещает задачи.
- **Бэклог** — реестр для разбора. Сверху «Входящие — разобрать»: новые задачи, которые нужно запланировать, взять в работу или отложить. Ниже «Бэклог — хранилище» одним списком: сначала раскрывающиеся папки проектов (клик по папке — показать её задачи), затем задачи без проекта. Колонки: ID, задача с фразой о влиянии, MoSCoW, сколько дней в бэклоге (старше 30 дней подсвечено), срок.
- **Проекты** — информационная вкладка: карточки проектов с прогрессом и ближайшим сроком. Выберите проект — ниже одним списком все его задачи по состоянию: в работе, готово к реализации, в разработке, на тестировании, запланировано, бэклог и входящие, сделано. Сверху — сколько задач всего, сколько сделано и сколько в работе. В режиме редактирования здесь же **＋ Новый проект** и ✎ у каждого проекта.
- **Архив** — закрытые задачи.

Клик по карточке открывает задачу целиком. В режиме редактирования в ней есть **✎ Изменить** и быстрые кнопки; без него — **✎ Редактировать** ведёт в редактор файла на GitHub. Ссылку на открытую задачу (`…/#BL-015`) можно переслать — она откроется сразу на этой карточке. Клавиша `/` — быстрый поиск.

**Цветовые сигналы срока:** 🔴 просрочено, сегодня или завтра · 🟠 до 3 дней · 🟡 до 7 дней · без цвета — дальше.

## 2. Рабочий день с бэклогом

1. **Утро, 2 минуты.** Дашборд → вкладка **«Спринт»**: проверьте задачи в работе и сроки. Колонки и статусы сами не меняются.
2. **Берёте задачу.** Открываете карточку, читаете «Суть» и «Контекст». Если задача ещё не в работе — **▶ В работу**.
3. **По ходу работы** отмечаете пункты чек-листа (`- [ ]` → `- [x]`) и дописываете в «Журнал» важное: решения, договорённости, ссылки.
4. **Упёрлись в других** — запишите в журнал, кого и чего ждёте. Если работу откладываете, нажмите **📅 Вернуть в план**, выберите **Запланировано** или **Отложено**, укажите срок и комментарий.
5. **Закончили** — **✓ Готово** с итогом. Задача сама уедет в архив с датой закрытия.

> Если «В работе» разрастается, верните менее срочные задачи в план и выберите для них колонку **Запланировано** или **Отложено**. Перенос дедлайна сам по себе колонку не меняет.

## 3. Как добавить задачу

Работаем комбинацией: **новые задачи — через Claude или дашборд, правки — сами в дашборде.**

### Способ 0. Прямо в дашборде — самый удобный

Нужен один раз включённый [режим редактирования](#режим-редактирования-на-дашборде). Кнопка **＋ Новая задача** откроет форму: название, статус, срок (календарь), MoSCoW, проект, тип, система, инициатор, влияние на бизнес, ссылка на Битрикс, единое поле «Описание» и материалы. Для статуса **Запланирована** выберите **Колонку плана**: **Запланировано** или **Отложено**. Номер `BL-…` присвоится сам.

### Способ 1. Через Claude (проект «Бэклог» в Claude) — для задач с контекстом

Напишите в свободной форме, можно переслать письмо или сообщение из чата. Claude:
- присвоит номер, определит тип, проект, систему;
- соберёт суть и контекст в одном разделе «Описание»;
- предложит оценку MoSCoW и срок (или спросит);
- сохранит в репозиторий, сводка и дашборд обновятся сами.

Лучше всего подходит, когда задач несколько или у задачи длинная предыстория.

### Способ 2. Форма «＋ Новая задача» — быстро, с телефона

1. Кнопка **＋ Новая задача** в README или на дашборде (нужно быть залогиненным в GitHub).
2. Заполнить **Название** — это единственное обязательное поле. Остальное по возможности: описание, MoSCoW, тип, проект, статус, срок (`15.10.2026`).
3. **Submit new issue.**
4. Через ~1 минуту робот создаст карточку в `tasks/`, ответит в заявке ссылкой на неё и закроет заявку.

Не знаете, что с задачей делать, — оставьте статус «Входящие», разберёте на неделе.
Форма принимает задачи **только от владельца репозитория** — заявки от других людей игнорируются.

### Способ 3. Вручную — не рекомендуется

Можно скопировать `templates/task.md` в `tasks/`, но тогда номер `BL-…` придётся подбирать самому. Проще первыми двумя способами.

## 4. Как изменить задачу

### Режим редактирования на дашборде

Дашборд умеет не только показывать задачи, но и менять их. Для этого нужен личный токен GitHub — ключ, который разрешает запись **только в этот репозиторий и только в файлы**.

**Один раз создать токен** (≈2 минуты):
1. [github.com → Settings → Developer settings → Fine-grained tokens → Generate new token](https://github.com/settings/personal-access-tokens/new)
2. **Token name** — `Бэклог — дашборд`; **Expiration** — 90 дней или свой срок.
3. **Repository access** → *Only select repositories* → `resan-revitech-backlog`.
4. **Permissions → Repository permissions → Contents** → *Read and write*.
5. **Generate token** и скопировать его (начинается с `github_pat_`; GitHub показывает его один раз).

**На каждом устройстве один раз:** дашборд → **🔑 Войти** → вставить токен → «Проверить и войти». Кнопка станет **✓ Редактирование**.

**Проекты:** на вкладке «Проекты» — **＋ Новый проект** (название, короткое название для меток, описание, статус, ссылки на страницу и репозиторий) и ✎ для изменения существующего. Новый проект сразу появляется в выпадающем списке «Проект» у задач, а после пересборки (~1 минута) — в README и в форме «＋ Новая задача» на GitHub. Если создавать задачу, находясь на вкладке «Проекты», выбранный проект подставится сам.

**Что появляется в карточке задачи:**
- **✎ Изменить** — форма со всеми полями: статус, MoSCoW и влияние, срок, проект, тип, система, инициатор, оценка, Битрикс, теги, текст разделов и новая запись в журнал;
- быстрые кнопки **📅 Запланировать** (колонка, срок и комментарий), **▶ В работу**, **📤 Готово к передаче**, **⚙️ В разработку**, **👀 В тестирование**, **🗂 В бэклог**, **✓ Готово**, **✕ Отменить** (для последних трёх — поле для итога или причины, оно уйдёт в журнал), у закрытых — **↺ Вернуть в работу**;
- **галочки чек-листа кликабельны** — отметка сохраняется сразу.

Смена статуса, MoSCoW и срока автоматически записывается в журнал задачи. После сохранения README и дашборд у всех обновятся примерно через минуту.

**Безопасность:**
- токен хранится **только в браузере этого устройства**, не попадает в репозиторий и в ссылки; гости и руководители, открывающие дашборд, видят его только для просмотра — кнопок редактирования у них нет;
- не вводите токен на общих и чужих компьютерах; выйти и стереть токен — нажать **✓ Редактирование → Выйти**;
- отозвать токен можно в любой момент на той же странице GitHub; когда срок токена истечёт, создайте новый и войдите заново;
- если задача за это время изменилась в другом месте (вы правили файл на GitHub, Claude внёс изменения), дашборд не затрёт их: подтянет свежую версию и наложит ваши правки сверху.

### Правка файла на GitHub

**С ПК**
1. Открыть задачу: из дашборда кнопка **✎ Редактировать**, или в репозитории `tasks/` → нужный файл → карандаш ✎ справа вверху.
2. Поменять нужные строки в шапке между `---` или текст ниже.
3. **Commit changes…** → ещё раз **Commit changes** (комментарий можно не писать).
4. Через ~1 минуту обновятся README, архив и дашборд.

**С телефона**
Откройте github.com в браузере телефона (не в приложении GitHub — оно не редактирует файлы), дальше так же: файл → ✎ → правка → **Commit changes**.

**Важно в шапке карточки:**
- не удаляйте строки `---` сверху и снизу шапки;
- после двоеточия — пробел: `status: done`;
- всё после ` # ` — комментарий-подсказка, его можно не трогать;
- дата — в формате `2026-10-15` (или `15.10.2026` — робот поймёт).

Статус и тип можно писать и по-русски: `в работе`, `запланирована`, `в разработке`, `готово`, `аналитика` и т. д. Колонка `priority` выбирается вручную: `next` — Запланировано, `later` — Отложено; работа и разработка используют `now` и `development`.

## 5. Шпаргалка: типовые действия

Проще всего — кнопками в карточке на дашборде (режим редактирования). Если правите файл на GitHub вручную:

| Хочу… | Кнопка в дашборде | Что поменять в файле |
|:--|:--|:--|
| Взять в работу | ▶ В работу | `status: in-progress` |
| Запланировать | 📅 Запланировать | `status: todo` + `deadline` |
| Отложить работу | 📅 Вернуть в план | `status: todo`, `priority: next` или `later`; в журнал — причина |
| Отложить, пока ничего не ясно | 🗂 В бэклог | `status: backlog` |
| Разобрать входящую задачу | 📅 / ▶ / 🗂 | заполнить суть, `moscow`, `impact`, `deadline`, затем статус |
| Перенести срок | ✎ Изменить → Срок | `deadline: 2026-10-20` + в журнал причину переноса |
| Переместить задачу между колонками | 📅 Изменить план → Колонка | `priority: next` или `later`, без привязки к дедлайну |
| Поменять оценку MoSCoW | ✎ Изменить | `moscow: must` / `should` / `could` / `wont` + при необходимости `impact` |
| Отметить шаг чек-листа | галочка в карточке | `- [ ] Шаг` → `- [x] Шаг` |
| Записать решение или договорённость | ✎ Изменить → «Новая запись в журнал» | строка в «Журнал»: `- 2026-09-30 — согласовали с …, что …` |
| Закрыть как выполненную | ✓ Готово | `status: done` + в журнал итог |
| Закрыть без выполнения | ✕ Отменить | `status: canceled` + в журнал причину |
| Вернуть задачу из архива | ↺ Вернуть в работу | поставить активный статус — задача сама вернётся в `tasks/` |
| Привязать к проекту | ✎ Изменить → Проект | `project: buh` или `project: ut-opt` |
| Добавить ссылку на Битрикс | ✎ Изменить | `bitrix: https://…` |

**Удалять файлы задач не нужно и нельзя** — для этого есть `canceled` и архив.

## 6. Поля карточки

| Поле | Значения | Заметки |
|:--|:--|:--|
| `id` | `BL-001`… | Присваивается автоматически, не менять |
| `title` | текст | 3–7 слов, с глагола, без кодов: «Проверить режим запуска конфигурации УТ» |
| `status` | `inbox` · `backlog` · `todo` · `in-progress` · `ready-for-development` · `in-development` · `in-testing` · `done` · `canceled` | см. ниже |
| `priority` | `now` · `ready` · `development` · `testing` · `next` · `later` | Ручная колонка спринта. Для запланированных задач — **Запланировано** или **Отложено**. Срок не меняет колонку |
| `moscow` | `must` · `should` · `could` · `wont` | Влияние на систему и бизнес, не зависит от сроков |
| `impact` | одна фраза | Чем задача важна для системы и бизнеса — показывается в карточке задачи |
| `type` | `analysis` аналитика · `dev` разработка · `consult` консультация · `research` исследование · `support` поддержка | |
| `project` | `buh` · `ut-opt` · пусто | Список — в `backlog.json` |
| `system` | свободно | `1С:УТ`, `1С:БП`, `Битрикс24`… — по нему работает фильтр |
| `initiator` | свободно | Кто поставил задачу |
| `created` | дата | Ставится автоматически |
| `deadline` | дата или пусто | Без срока задача стоит в конце своей группы |
| `estimate` | `2h`, `1d`, `3d` | Оценка трудозатрат |
| `bitrix` | ссылка | Если задача есть в Битриксе |
| `tags` | `[отчёты, регламенты]` | Ищутся поиском на дашборде |
| `closed` | дата | Ставится автоматически при закрытии |

**Статусы**

| Статус | Значит | Где видно |
|:--|:--|:--|
| 📥 `inbox` Входящие | Только что поступила, ещё не разобрана | «Бэклог» → «Входящие — разобрать» |
| 🗂 `backlog` Бэклог | Хранилище: по задаче пока ничего не ясно — ни сроков, ни очереди | «Бэклог» → «Хранилище» |
| 📅 `todo` Запланирована | Ждёт начала. Колонка плана выбирается вручную | «Спринт» → «Запланировано» или «Отложено» |
| 🎯 `in-progress` В работе | Делаю сейчас; горизонт всегда «В работе» | «Спринт» → «В работе» |
| 📤 `ready-for-development` Готово к реализации | Можно передавать разработчикам | «Спринт» → «Готово к реализации» |
| 🛠 `in-development` В разработке | Задача передана разработчикам; срок не меняет это состояние | «Спринт» → «В разработке» |
| 👀 `in-testing` На тестировании | Результат передан на проверку | «Спринт» → «На тестировании» |
| ✅ `done` Готово | Выполнено | Архив |
| 🚫 `canceled` Отменено | Не нужно / потеряло смысл | Архив |

**Правила, которые держат бэклог в порядке:**
- **колонки выбираются вручную:** дедлайн не меняет статус или колонку задачи;
- бэклог и входящие появляются в спринте после ручного планирования, взятия в работу или передачи в разработку.

**Разделы новой карточки:** Описание · Материалы · Журнал. В форме создания нет оценки, тегов, следующего шага, зависимостей, чек-листа и критериев готовности. Ранее созданные разделы и данные сохраняются и остаются доступны при редактировании старых задач. Журнал — самое ценное через месяц: туда пишем решения, договорённости и перенос сроков с датой.

**Как называть задачи:** 3–7 слов, с глагола, чтобы по названию было ясно, что сделать («Проверить режим запуска конфигурации УТ»). Без кодов: ссылки на другие задачи и на пункты проектов — названиями в кавычках «…». Задачи не удаляем: дубли объединяем, закрывая одну из них со статусом «Отменено» и пометкой, с чем объединена; вопросы закрываем с пометкой, чем они закончились.

## 7. Приоритеты: горизонт и MoSCoW

У задачи две независимые оценки. Они отвечают на разные вопросы и не подменяют друг друга.

### Колонка спринта (`priority`) — выбирается вручную

Колонка определяется действием пользователя и не зависит от дедлайна:

| Колонка | Какие задачи |
|:--|:--|
| 🔴 **В работе** | задачи, взятые в работу кнопкой **▶ В работу** |
| 📤 **Готово к реализации** | задачи, подготовленные к передаче кнопкой **📤 Готово к передаче** |
| 🟣 **В разработке** | задачи, переданные разработчикам кнопкой **⚙️ В разработку**, независимо от срока |
| 👀 **На тестировании** | задачи, переданные на проверку кнопкой **👀 В тестирование** |
| 🟠 **Запланировано** | запланированные задачи, для которых вручную выбрана колонка **Запланировано** |
| ⚪ **Отложено** | запланированные задачи, для которых вручную выбрана колонка **Отложено** |

В «Спринте» первые четыре колонки идут слева направо: «В работе», «Готово к реализации», «В разработке», «На тестировании». «Запланировано» и «Отложено» пока остаются ниже в той же вкладке; бэклог и входящие — во вкладке «Бэклог».

**Порядок внутри колонки:** сначала **срок** (ближайший сверху), при одинаковом сроке — **MoSCoW** (Must → Should → Could → Won't). Срок важнее MoSCoW: задача Should со сроком через 2 дня стоит выше задачи Must со сроком через неделю. Задачи без срока идут по MoSCoW.

**Ручное планирование.** В карточке нажмите **📅 Вернуть в план** или **📅 Изменить план**, выберите колонку **Запланировано** или **Отложено**, срок и комментарий. Выбор колонки и изменение срока записываются в журнал. Даже просроченная задача остаётся в выбранной колонке. Для перехода в **В работе** используется **▶ В работу**, в **В разработке** — **⚙️ В разработку**.

В формах создания и редактирования поле **Колонка плана** доступно для статуса **Запланирована**. При изменении одного только дедлайна выбранная колонка сохраняется.

### MoSCoW (`moscow`) — насколько задача важна для системы и бизнеса

Оценка влияния: что будет с системой и бизнесом, если задачу не сделать. **Не зависит** от сроков и того, когда я за неё возьмусь. Оценка видна в карточке задачи и в README. Отдельной вкладки MoSCoW на дашборде нет.

| | Когда ставить | Пример |
|:--|:--|:--|
| 🟥 **Must** | Без этого система или бизнес под угрозой: остановка работы, юридический риск, прямые потери, риск для стабильности базы | Зависание 1С у склада, счета-фактуры на аванс (НК РФ) |
| 🟧 **Should** | Важно, есть заметный эффект, но есть обходной путь (ручной труд, терпимая нагрузка) | Автоматический обмен УТ → БП (сейчас вручную) |
| 🟦 **Could** | Улучшение, эффект умеренный или ещё не измерен | Дельта-обмен с сайтами |
| ⬜ **Won't** | Влияние несущественно — делать не стоит, пока не изменятся условия | |

- В поле `impact` одной фразой — **чем именно** задача важна. Это видно в карточке задачи и в README.
- **Ориентир: Must — не больше четверти активных задач.** Если Must становится всё, оценка перестаёт работать.
- Задача может быть **Must, но в бэклоге или «Отложено»** (важна, но срока нет — например, Н2 по НДС) или **Could, но «В работе»** (задачу взяли в работу). Это нормально: горизонт — про время, MoSCoW — про ценность. Must без срока — повод обсудить с руководством, когда ей заняться: это осознанно принятый риск.

## 8. Ритм: день, неделя, месяц

| Когда | Что делать | Время |
|:--|:--|:--|
| **Каждый день** | «Спринт» → «В работе»: что в работе и что горит. Отметить сделанное, закрыть готовое | 2–5 мин |
| **Раз в неделю** (например, пятница) | Разобрать входящие; вручную выбрать задачи для **В работе**, **Запланировано** и **Отложено**. Проверить сроки и журнал договорённостей | 15–20 мин |
| **Раз в месяц** | Просмотреть бэклог (колонка «В бэклоге» — сколько дней лежит) и оценки MoSCoW в карточках: что устарело — отменить с причиной, Must без срока — обсудить. Архив за месяц — готовый отчёт о сделанном | 20 мин |

Еженедельный разбор удобно делать с Claude: «Давай разберём бэклог» — пройдёмся по входящим, горящим и ожидающим, и Claude внесёт изменения пачкой.

## 11. Если что-то пошло не так

| Проблема | Что делать |
|:--|:--|
| Дашборд пишет «токен не принят» | Токен истёк или отозван — создайте новый и войдите заново |
| «У токена нет права записи» | При создании токена не выбрано *Contents → Read and write* или не выбран этот репозиторий — пересоздайте токен |
| Сохранил в дашборде, а после обновления страницы вижу старое | Дашборд пересобирается ~1 минуту после сохранения — обновите страницу чуть позже |
| Сводка или дашборд не обновились | Подождать 1–2 минуты и обновить страницу. Если нет — вкладка **Actions** в репозитории: красный крестик = ошибка, открыть и посмотреть шаг |
| Внизу README «⚠️ Замечания к оформлению задач» | Там написано, какой файл и что не так (опечатка в статусе, неверная дата). Поправить — замечание исчезнет |
| Задача из формы не появилась | Проверить, что заявка создана из шаблона «＋ Новая задача» и под вашим аккаунтом. Иначе — Actions |
| Случайно удалил файл или испортил карточку | Ничего не теряется: вся история хранится в git. Попросите Claude восстановить, или на GitHub: файл → **History** → нужная версия |
| Дашборд не открывается совсем | Settings → Pages → Source должно быть **GitHub Actions** |

**Сборка, для справки.** После изменения робот (GitHub Actions) обновляет README и дашборд, переносит закрытые задачи в архив и возвращает переоткрытые в активный список. Ежедневная сборка сохраняется, но дедлайны больше не меняют статусы и колонки.
