## 1. Где что смотреть

| Что | Зачем | Когда открывать |
|:--|:--|:--|
| **[Дашборд](https://tork059.github.io/resan-revitech-backlog/)** | Главный рабочий экран: что горит, что в работе, что следующее. Поиск и фильтры, полная карточка по клику | Каждый день, с ПК и телефона |
| **[README](../README.md)** — главная страница репозитория | Та же сводка текстом: проекты, «Горит», таблицы по горизонту и MoSCoW | Когда удобнее таблица или нужен быстрый взгляд из GitHub |
| **Карточка задачи** — файл в `tasks/` | Весь контекст: суть, зачем, чек-лист, критерии готовности, материалы, журнал | Перед тем как взяться за задачу |
| **[Архив](../archive/README.md)** | Все закрытые задачи по месяцам, с датой закрытия | При отчёте о сделанном |

**Вкладки дашборда**

- **Фокус** — проекты с прогрессом, «Горит и ещё не в работе», «В работе», «Следующие по очереди» (топ-6), «Ожидание». Начинайте день отсюда.
- **Горизонт** — три колонки: Сейчас / Далее / Потом, внутри по очерёдности и сроку. Внизу — неразобранные «Входящие».
- **MoSCoW** — четыре колонки Must / Should / Could / Won't: влияние задачи на систему и бизнес. На карточке — одна фраза «чем важна» и горизонт.
- **Статусы** — канбан: Входящие → Бэклог → В работе → Ожидание.
- **Сроки** — просрочено / ближайшие 7 дней / 8–21 день / позже / без срока.
- **Архив** — закрытые задачи.

Клик по карточке открывает задачу целиком. Кнопка **✎ Редактировать** ведёт прямо в редактор файла на GitHub. Ссылку на открытую задачу (`…/#BL-015`) можно переслать — она откроется сразу на этой карточке. Клавиша `/` — быстрый поиск.

**Цветовые сигналы срока:** 🔴 просрочено, сегодня или завтра · 🟠 до 3 дней · 🟡 до 7 дней · без цвета — дальше.

## 2. Рабочий день с бэклогом

1. **Утро, 2 минуты.** Дашборд → вкладка «Фокус». Смотрите блок «Горит»: это задачи с истёкшим сроком или сроком в ближайшие 3 дня, которые ещё не в работе.
2. **Берёте задачу.** Открываете карточку, читаете «Суть» и «Контекст». Ставите `status: in-progress` (см. [раздел 4](#4-как-изменить-задачу)).
3. **По ходу работы** отмечаете пункты чек-листа (`- [ ]` → `- [x]`) и дописываете в «Журнал» важное: решения, договорённости, ссылки.
4. **Упёрлись в других** (ждёте ответ, доступ, данные) — `status: waiting` и строка в журнал, кого и чего ждёте.
5. **Закончили** — `status: done` и строка в журнал с результатом. Задача сама уедет в архив с датой закрытия.

> Правило: одновременно в работе — не больше 2–3 задач. Если «В работе» разрастается, часть на самом деле в «Ожидании» или «Бэклоге».

## 3. Как добавить задачу

Три способа. Работаем комбинацией: **новые задачи — через Claude или форму, мелкие правки — сами на GitHub.**

### Способ 1. Через Claude (проект «Бэклог» в Claude) — для задач с контекстом

Напишите в свободной форме, можно переслать письмо или сообщение из чата. Claude:
- присвоит номер, определит тип, проект, систему;
- разложит текст по разделам «Суть / Контекст / Что сделать / Критерии готовности»;
- предложит горизонт, оценку MoSCoW и срок (или спросит);
- сохранит в репозиторий, сводка и дашборд обновятся сами.

Лучше всего подходит, когда задач несколько или у задачи длинная предыстория.

### Способ 2. Форма «＋ Новая задача» — быстро, с телефона

1. Кнопка **＋ Новая задача** в README или на дашборде (нужно быть залогиненным в GitHub).
2. Заполнить **Название** — это единственное обязательное поле. Остальное по возможности: суть, горизонт, MoSCoW, тип, проект, статус, срок (`15.10.2026`), оценка.
3. **Submit new issue.**
4. Через ~1 минуту робот создаст карточку в `tasks/`, ответит в заявке ссылкой на неё и закроет заявку.

Не знаете горизонт — оставьте статус «Входящие», разберёте на неделе.
Форма принимает задачи **только от владельца репозитория** — заявки от других людей игнорируются.

### Способ 3. Вручную — не рекомендуется

Можно скопировать `templates/task.md` в `tasks/`, но тогда номер `BL-…` придётся подбирать самому. Проще первыми двумя способами.

## 4. Как изменить задачу

**С ПК**
1. Открыть задачу: из дашборда кнопка **✎ Редактировать**, или в репозитории `tasks/` → нужный файл → карандаш ✎ справа вверху.
2. Поменять нужные строки в шапке между `---` или текст ниже.
3. **Commit changes…** → ещё раз **Commit changes** (комментарий можно не писать).
4. Через ~1 минуту обновятся README, архив и дашборд.

**С телефона**
Откройте github.com в браузере телефона (не в приложении GitHub — оно не редактирует файлы), дальше так же: файл → ✎ → правка → **Commit changes**.

**Важно в шапке карточки:**
- не удаляйте строки `---` сверху и снизу шапки;
- после двоеточия — пробел: `status: done`;
- всё после ` # ` — комментарий-подсказка, его можно не трогать;
- дата — в формате `2026-10-15` (или `15.10.2026` — робот поймёт).

Статус, горизонт и тип можно писать и по-русски: `в работе`, `ожидание`, `готово`, `сейчас`, `далее`, `потом`, `разработка` и т. д.

## 5. Шпаргалка: типовые действия

| Хочу… | Что поменять в карточке |
|:--|:--|
| Взять в работу | `status: in-progress` |
| Поставить на паузу — ждём других | `status: waiting` + в журнал: кого и чего ждём |
| Вернуть в очередь | `status: backlog` |
| Разобрать входящую задачу | заполнить суть, `priority`, `moscow`, `impact`, `deadline` → `status: backlog` |
| Перенести срок | `deadline: 2026-10-20` + в журнал причину переноса |
| Сменить горизонт | `priority: now` (сейчас) / `next` (далее) / `later` (потом) |
| Поменять оценку MoSCoW | `moscow: must` / `should` / `could` / `wont` + при необходимости `impact` |
| Задать очерёдность внутри горизонта | `order: 1` (первая), `order: 2`… |
| Отметить шаг чек-листа | `- [ ] Шаг` → `- [x] Шаг` |
| Записать решение или договорённость | строка в «Журнал»: `- 2026-09-30 — согласовали с …, что …` |
| Закрыть как выполненную | `status: done` + в журнал итог |
| Закрыть без выполнения | `status: canceled` + в журнал причину |
| Вернуть задачу из архива | открыть файл в `archive/<год>/`, поставить активный статус — задача сама вернётся в `tasks/` |
| Привязать к проекту | `project: buh` или `project: ut-opt` |
| Добавить ссылку на Битрикс | `bitrix: https://…` |

**Удалять файлы задач не нужно и нельзя** — для этого есть `canceled` и архив.

## 6. Поля карточки

| Поле | Значения | Заметки |
|:--|:--|:--|
| `id` | `BL-001`… | Присваивается автоматически, не менять |
| `title` | текст | Коротко, по сути. Коды проекта в начале: `Н1·1.2 …`, `К1-3 …` |
| `status` | `inbox` · `backlog` · `in-progress` · `waiting` · `done` · `canceled` | см. ниже |
| `priority` | `now` · `next` · `later` | Горизонт — когда возьмусь. См. [раздел 7](#7-приоритеты-горизонт-и-moscow) |
| `moscow` | `must` · `should` · `could` · `wont` | Влияние на систему и бизнес, не зависит от сроков |
| `impact` | одна фраза | Чем задача важна для системы и бизнеса — показывается во вкладке MoSCoW |
| `order` | `1`, `2`, `3`… или пусто | Очерёдность внутри горизонта: `1` — первая. Задачи без номера идут после пронумерованных, по сроку |
| `type` | `analysis` аналитика · `dev` разработка · `consult` консультация · `research` исследование · `support` поддержка | |
| `project` | `buh` · `ut-opt` · пусто | Список — в `backlog.json` |
| `system` | свободно | `1С:УТ`, `1С:БП`, `Битрикс24`… — по нему работает фильтр |
| `initiator` | свободно | Кто поставил задачу |
| `created` | дата | Ставится автоматически |
| `deadline` | дата или пусто | Без срока задача стоит в конце своей группы |
| `estimate` | `2h`, `1d`, `3d` | Оценка трудозатрат |
| `bitrix` | ссылка | Если задача есть в Битриксе |
| `tags` | `[отчёты, регламенты]` | Ищутся поиском на дашборде |
| `closed` | дата | Ставится автоматически при закрытии |

**Статусы**

| Статус | Значит | Где видно |
|:--|:--|:--|
| 📥 `inbox` Входящие | Записано, но не разобрано: нет ясности по сути, приоритету, сроку | README внизу, дашборд «Горизонт» внизу |
| 🗂 `backlog` Бэклог | Разобрано, понятно что делать, ждёт своей очереди | Таблицы Сейчас / Далее / Потом |
| 🎯 `in-progress` В работе | Делаю сейчас | Отдельный блок наверху |
| ⏳ `waiting` Ожидание | Не могу продолжить без других | Отдельный блок |
| ✅ `done` Готово | Выполнено | Архив |
| 🚫 `canceled` Отменено | Не нужно / потеряло смысл | Архив |

**Разделы карточки:** Суть · Контекст · Что сделать (чек-лист) · Критерии готовности · Материалы · Журнал. Журнал — самое ценное через месяц: туда пишем решения, договорённости и перенос сроков с датой.

## 7. Приоритеты: горизонт и MoSCoW

У задачи две независимые оценки. Они отвечают на разные вопросы и не подменяют друг друга.

### Горизонт (`priority`) — когда я за это возьмусь

| | Значит | Правило |
|:--|:--|:--|
| 🔴 **Сейчас** `now` | Эта неделя, в фокусе | Не больше 5–7 задач. Новая задача в «Сейчас» → какая-то уходит в «Далее» |
| 🟠 **Далее** `next` | Ближайший месяц | Отсюда берём, когда освобождается место в «Сейчас» |
| ⚪ **Потом** `later` | Когда-нибудь, без срока | Не удаляется; пересматривается раз в месяц |

- Внутри горизонта задачи идут по **очерёдности** `order` (1 — первая), затем по **сроку**.
- **Срок** (`deadline`) — к какому числу нужно. Всё, что просрочено или горит в ближайшие 3 дня, поднимается в блок «Горит» независимо от горизонта.
- Автоматически горизонт **не меняется** — переносите сами (или через Claude на еженедельном разборе).

### MoSCoW (`moscow`) — насколько задача важна для системы и бизнеса

Оценка влияния: что будет с системой и бизнесом, если задачу не сделать. **Не зависит** от сроков, очерёдности и того, когда я за неё возьмусь. Вкладка **MoSCoW** на дашборде и раздел «⚖️ MoSCoW» в README показывают, что реально критично.

| | Когда ставить | Пример |
|:--|:--|:--|
| 🟥 **Must** | Без этого система или бизнес под угрозой: остановка работы, юридический риск, прямые потери, риск для стабильности базы | Зависание 1С у склада, счета-фактуры на аванс (НК РФ) |
| 🟧 **Should** | Важно, есть заметный эффект, но есть обходной путь (ручной труд, терпимая нагрузка) | Автоматический обмен УТ → БП (сейчас вручную) |
| 🟦 **Could** | Улучшение, эффект умеренный или ещё не измерен | Дельта-обмен с сайтами |
| ⬜ **Won't** | Влияние несущественно — делать не стоит, пока не изменятся условия | |

- В поле `impact` одной фразой — **чем именно** задача важна. Это видно на карточке во вкладке MoSCoW и в README.
- **Ориентир: Must — не больше четверти активных задач.** Если Must становится всё, оценка перестаёт работать.
- Задача может быть **Must, но «Потом»** (важна, но сейчас не до неё — например, Н2 по НДС) или **Could, но «Сейчас»** (дешёвая и срочная). Это нормально: горизонт — про время, MoSCoW — про ценность. Расхождения стоит обсуждать с руководством: Must в «Потом» — это осознанно принятый риск.

## 8. Ритм: день, неделя, месяц

| Когда | Что делать | Время |
|:--|:--|:--|
| **Каждый день** | Дашборд → «Фокус»: «Горит», «В работе». Обновить статусы того, что сдвинулось | 2–5 мин |
| **Раз в неделю** (например, пятница) | Разобрать «Входящие» → в бэклог. Пересобрать «Сейчас» на неделю (≤ 5–7 задач), проверить, нет ли Must в «Потом» без причины. Проверить «Ожидание» — кого пнуть. Проставить сроки, где их нет | 15–20 мин |
| **Раз в месяц** | Просмотреть «Потом» и пересмотреть оценки MoSCoW: что устарело — `canceled` с причиной. Посмотреть архив за месяц — готовый отчёт о сделанном | 20 мин |

Еженедельный разбор удобно делать с Claude: «Давай разберём бэклог» — пройдёмся по входящим, горящим и ожидающим, и Claude внесёт изменения пачкой.

## 9. Работа через Claude

Всё делается в проекте «Бэклог» в Claude. Примеры запросов:

| Что нужно | Как попросить |
|:--|:--|
| Новая задача | «Добавь задачу: склад просит отчёт по остаткам по ячейкам, до 15.10, инициатор Петров» |
| Пачка задач | Список текстом или пересланное письмо: «Заведи задачи из этого письма» |
| Сменить статус/срок | «BL-015 в работу», «BL-002 перенеси на 20.10, Иннотех задержал файл правил» |
| Закрыть с итогом | «Закрой BL-024: режим запуска — обычное приложение, контур К3 переопределяем» |
| Дописать контекст | «Добавь в BL-026: по ТЖ самый тяжёлый запрос — остатки в динамическом списке» |
| Разбор | «Что у меня горит?», «Что взять следующим?», «Давай еженедельный разбор» |
| Отчёт | «Что сделано за сентябрь?» — Claude соберёт из архива |
| Синхронизация с проектом | «Обновилась страница проекта по бухгалтерии — сверь задачи Н1» |

## 10. Проекты

Задачи больших проектов привязываются полем `project`. У каждого проекта в README и на дашборде — прогресс (готово / всего), число активных задач, ближайший срок и ссылка на страницу проекта. Клик по карточке проекта на дашборде фильтрует задачи этого проекта.

| Ключ | Проект | Страница |
|:--|:--|:--|
| `buh` | Автоматизация бухгалтерии | [resan-revitech-buh](https://tork059.github.io/resan-revitech-buh/) |
| `ut-opt` | Оптимизация 1С:УТ | [resan-ut-optimization](https://tork059.github.io/resan-ut-optimization/) |

**Новый проект** проще всего добавить через Claude («Заведи проект …»). Вручную: добавить запись в `backlog.json` → `projects` и название в выпадающий список `.github/ISSUE_TEMPLATE/task.yml`.

Коды в названиях задач (`Н1·1.3`, `К1-9`, `В-12`) совпадают с кодами на страницах проектов — по ним легко найти место в проектном документе.

## 11. Если что-то пошло не так

| Проблема | Что делать |
|:--|:--|
| Сводка или дашборд не обновились | Подождать 1–2 минуты и обновить страницу. Если нет — вкладка **Actions** в репозитории: красный крестик = ошибка, открыть и посмотреть шаг |
| Внизу README «⚠️ Замечания к оформлению задач» | Там написано, какой файл и что не так (опечатка в статусе, неверная дата). Поправить — замечание исчезнет |
| Задача из формы не появилась | Проверить, что заявка создана из шаблона «＋ Новая задача» и под вашим аккаунтом. Иначе — Actions |
| Случайно удалил файл или испортил карточку | Ничего не теряется: вся история хранится в git. Попросите Claude восстановить, или на GitHub: файл → **History** → нужная версия |
| Дашборд не открывается совсем | Settings → Pages → Source должно быть **GitHub Actions** |

**Автоматика, для справки.** После каждого изменения робот (GitHub Actions) за ~1 минуту: переносит закрытые задачи в `archive/<год>/` и ставит дату закрытия; возвращает переоткрытые задачи в `tasks/`; пересобирает README, архив и дашборд. Раз в сутки, в 00:05 по Екатеринбургу, сводка пересобирается сама, чтобы «через N дн.» было актуальным. Дашборд пересчитывает сроки по текущей дате при каждом открытии.

- **Что критично для системы и бизнеса** — вкладка **MoSCoW** на дашборде: у каждой задачи оценка Must / Should / Could / Won't и одной фразой — чем она важна.
- **Прогресс проектов** — таблица «Проекты» в README и карточки проектов на дашборде.
- **Что сделано** — [архив](../archive/README.md) по месяцам.
- **Детали по любой задаче** — клик по карточке: суть, контекст, чек-лист, журнал решений.
- Новую задачу можно передать как обычно; в бэклог её внесёт исполнитель, с приоритетом и сроком.
